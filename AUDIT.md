# AUDIT

Register of the correction roadmap for `zig-algebra`, and what happened to it.

Initial audit: 2026-09-25. Target Zig: 0.16.0.

**This file is checked by a gate.** `zig build audit-check` runs
`scripts/audit_verify.py` against it, and the CI job `audit-ledger` runs the same
thing on every push. It is the fourth difference between a register and a gate:
a row that stays open is a row with a number behind it, and nothing fails while
the number and the rows agree without anybody deciding.

What the gate enforces, and each rule exists because it caught something:

- Every row carries a **closing criterion**: the observable that was checked. A
  row with an empty cell is an error, not a style question.
- An `open` row's criterion may not restate the item. If the only way to satisfy
  it is to re-read the sentence, it is not a criterion.
- A `decision` row must **name an owner**. A decision with no owner is an open
  row wearing a different label.
- The **declared counts** in the comment below must match the rows.
- Every `git show <ref>:<path>` in this file **must resolve**. This rule was
  added because two of them did not.

## Why this file exists

The roadmap was a single document with 105 items and checkboxes. A rewrite
dissolved it into scattered files, and the loss of the enumerator was not
noticed for a week. This is the finding, not the defect:

> A list that gets rewritten into scattered notes is a regression in
> verifiability, and it does not look like one.

## What the rewrite cost, and what it did not

It did not lose corrections. Every one of the 99 marked items was, as far as
can be established, closed.

It lost the ability to say **how many** were closed. The count lived in the
document, and the document was dissolved. From the rewrite onward, "the
pending items live in fifteen places and no file enumerates them" was an
inference; with the original in hand it is a comparison, and the comparison
goes the other way.

The original had a duplicate `## [0.5.1]` section, and nothing in the toolchain
was watching for it. See row 14.

## The original

order they were found, each with a file and line reference into a tree that no

was, not at where the code is now.
