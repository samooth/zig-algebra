## Needs an instrument before it can be answered

**Asserts removed in ReleaseFast**

> No assert is compiled out in `ReleaseFast` such that an out-of-range value
> passes unchecked.

The assert ledger counts the asserts that are *present*. This question is about
the ones that disappear, which the ledger does not count. **This is not an
unfinished task; it is a question with no instrument.** Deciding whether to
build one, or to declare the question unanswerable and write down why, is the
decision.

**Constant-time claims**

> Every constant-time claim in the documentation is backed by a test or by an
> assembly audit.

Nothing in this repository measures it. The claims are in the documentation and
there is no check behind any of them.

**Rejection sampling cannot hang**

> No test can hang on rejection sampling.

RNG is bounded. Field and transcript are not, and the failure mode would be a
gate that times out, which from the outside is indistinguishable from a gate
that passed.

**Security items have regression tests**

> No critical security finding lacks a test that fails without the fix.

Needs an enumeration of what counts as critical, which does not exist yet.

## Can be done

**Public validation asserts become typed errors**

Remaining validation asserts that can fail on public input should return
errors instead. Some already do; this is the remainder.

**Path packages of the submodules are reproducible**

`libs/*/build.zig.zon` still carry path dependencies. Reproducing a build from
a clean clone needs no network and no local state.

**External points are validated**

On-curve, subgroup membership, and encoding, for points that arrive from
outside. Without it a proof can be handed a point that is not in the group.

**Serialisers have resource limits**

Input length bounds, and freeing on every error path. A serialiser that
allocates before it bounds its input is a denial of service with a proof
attached.
