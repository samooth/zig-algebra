# AGENTS.md — Atemporal Instructions for zig-field

## Purpose
This file contains enduring instructions for any agent (human or AI) working on the zig-field repository. These instructions apply regardless of the current state of the codebase.

## Core Principles

### 1. Correctness First
- All arithmetic must be mathematically correct. Run `zig build test` before committing.
- Prefer correct but slow code over fast but buggy code.
- Add tests for every new feature and every bug fix.

### 2. No External Dependencies
- Only the Zig standard library is allowed.
- Do not add C dependencies, Rust crates, or other language bindings.
- If a feature requires external code, implement it in pure Zig.

### 3. Comptime-First Design
- All constants (modulus, R², m₀⁻¹, two-adicity, odd part) are computed at comptime.
- Use `comptime_int` for intermediate calculations; cast to fixed-width types at the end.
- Field types are generated by `Field(comptime modulus)` — the modulus is a compile-time parameter.

### 4. Dual Backend Architecture
- **Small fields** (< 2^64): native `u64` with fast reduction. Mersenne primes (`2^k - 1`) use the classic split reduction `(lo + hi) mod p`.
- **Large fields** (≥ 2^64): Montgomery arithmetic over `[N]u64` limbs. CIOS multiplication with per-iteration shifting.
- Both backends expose identical APIs — the caller never sees the difference.

### 5. Extension Fields
- `QuadraticExtension(BaseField, non_residue)` with `v² = non_residue`.
- `CubicExtension(BaseField, non_residue)` with `v³ = non_residue`.
- Karatsuba multiplication for quadratic; closed-form inverse for both.
- `primitiveRootOfUnity` for extensions: embeds base roots when possible, otherwise finds non-residue in the extension.

### 6. Roots of Unity
- Only power-of-two roots are supported (what NTTs need).
- Algorithm: find quadratic non-residue `z` by exhaustive search, then `z^((p-1)/2^t)` has exact order `2^t`.
- No factorization of `p-1` is required.
- For extensions, use `(p^d - 1)/2^t` where `d` is the extension degree.

## Coding Conventions

### Naming
- Types: `PascalCase` (`Field`, `QuadraticExtension`)
- Functions/Methods: `camelCase` (`fromInt`, `primitiveRootOfUnity`)
- Constants: `SCREAMING_SNAKE_CASE` (`MODULUS`, `TWO_ADICITY`)
- Struct fields: `camelCase` (`limbs`, `c0`, `c1`)

### Memory
- No heap allocations in the hot path.
- Fixed-size arrays `[N]u64` for limbs.
- All functions are pure (no global state).

### Error Handling
- Use `!T` for operations that can fail (e.g., `fromBytes`, `sqrt`).
- Use `std.debug.assert` for invariants that should never fail in correct usage.
- Panic only for unreachable code or violated preconditions.

### Testing
- Property-based tests against `u512`/`u1024` reference arithmetic.
- Test each predefined field: add, sub, mul, inv, pow, legendre, sqrt, roots of unity.
- Test extension identities: `i² = -1`, `j² = -i`, conjugate, distributivity.
- Serialization round-trips (`toBytes` ↔ `fromBytes`).

## Build & CI
- `zig build test` — run all tests in Debug mode
- `zig build bench -Doptimize=ReleaseFast` — run benchmarks
- `zig fmt --check` — formatting check (enforced in CI)

## Adding a New Prime Field

1. Add the modulus as a constant in `src/predef/<name>.zig`:
   ```zig
   pub const MyField = field.Field(0x...);
   ```
2. Export from `src/predef/predef.zig` and `src/lib.zig`.
3. Add tests in `tests/field_test.zig` using `testFieldArithmetic(MyField)`.

## Adding a New Extension

1. Instantiate in `src/extension.zig`:
   ```zig
   pub const MyExt = QuadraticExtension(BaseField, non_residue);
   ```
2. Export from `src/lib.zig`.
3. Add tests in `tests/extension_test.zig`.

## Common Pitfalls

- **Montgomery `fromMontgomery`**: Multiply by canonical `1` (limb `[1, 0, ...]`), NOT by `R mod p`. The latter is the Montgomery form of 1.
- **Signed division**: Use `@divExact` for `i128` / comptime_int in ReleaseFast.
- **Debug prints in comptime**: `std.debug.print` cannot run at comptime. Remove before committing.
- **Overflow in small fields**: Goldilocks and similar fields near `2^64` need `u128` intermediates for add/sub.
- **Test iteration counts**: Keep Debug mode iterations low (≤50) to avoid timeouts.
